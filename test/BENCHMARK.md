# 网关压测记录

## 指标口径

`1_to_n.py` 的聚合转发有效吞吐为：所有 Monitor 完整解析并校验通过的 `VideoFrame` 总字节数，除以从 Collector 开始发送第一帧到最后一个 Monitor 收齐目标帧数的时间。

这不是通用最大吞吐量。记录结果时必须同时记录拓扑、帧大小、帧数、构建模式、机器和网络环境。

## 运行方式

先启动网关：

```bash
./build/gateway_server
```

再运行 1→N 扇出测试：

```bash
python3 test/1_to_n.py -n 2 -m 1000
```

建议按 1→1、1→2、1→10、1→50 逐级测试。每一级先确认每个 Monitor 收齐所有帧，再提高规模。

### FANOUT-2026-07-12-01：同机 1→N 扇出边界摸底

- Git 提交：`81fc29c`。
- 构建模式：Debug（当前 CMake 显式使用 `-g -O0`）。
- 环境：Ubuntu Linux 6.17.0-14-generic，Intel Core i5-13490F；Collector、Gateway 与所有 Monitor 均在同一台机器，通过 `127.0.0.1` 通信。
- 负载：1 Collector，64 KiB payload 的 VideoFrame，每个 Monitor 目标 1000 帧；聚合有效吞吐按本文档的指标口径计算。

### 结论

在上述 Debug / 同机 loopback / 64 KiB / 每端 1000 帧条件下，本次测试成功完成到 1→62；1→64 连续两次触发高水位线保护并发生未收齐。应至少重复 1→62 三次后，再宣称稳定上限。该结论描述的是当前测试条件下的扇出边界，不代表真实网络环境或 Release 构建下的绝对容量。
